# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page static site: a twelve-chapter illustrated history of weak gravitational
lensing, published to GitHub Pages. There is no build system, no package manager, no
test suite and no dependencies to install. The work here is almost entirely **content
and layout inside one file**, `index.html` (~350 KB, ~15,000 words of prose plus ~240 references).

Run it with `python3 -m http.server 8000` and open <http://localhost:8000/>. Serve it
rather than opening the file directly — that is how Pages serves it, and `file://`
introduces path differences that do not exist in production.

## The format is Claude Design, not plain HTML

`index.html` is a Claude Design component file (originally `Weak Lensing History.dc.html`).
This is the single most important thing to understand before editing it:

- The page body lives inside an `<x-dc>` wrapper, and a `<script type="text/x-dc">`
  block at the bottom defines a `Component extends DCLogic` class.
- `support.js` fetches React and ReactDOM UMD from unpkg **at page load** and mounts
  that component. Nothing renders without network access. (Babel is fetched lazily only
  for JSX `x-import`s; this page has none, so it never loads.)
- Consequently the page renders blank in any sandbox without outbound network. That is
  not a bug in the page.

**Do not touch the `<script type="text/x-dc">` block** unless the task is specifically
about behaviour. It wires three things by `data-` attribute selector, and those
attributes are the contract between markup and script:

| Attribute | Used for |
|---|---|
| `data-rail` / `data-rail-link` / `data-dot` | Sticky chapter rail; highlights the active chapter on scroll |
| `data-compare` / `data-compare-top` / `data-compare-handle` | The Bullet Cluster before/after slider |
| `data-aside` / `data-aside-mark` | Collapsible "More detail" blocks; toggles the `+`/`−` mark |

Adding a chapter or an aside means reproducing these attributes exactly, or the feature
silently stops working.

## Editing the page

All styling is **inline `style=""` attributes** (~870 of them) — deliberate, because this
is how Claude Design round-trips. There is no separate stylesheet to edit for page layout;
the only stylesheet is the design system's tokens.

The page was originally generated by Python builder scripts, but **those scripts are not
in this repo** and there is nothing to re-run. `index.html` is now the source of truth and
is maintained by editing it directly.

### Chapter structure

Chapters are `<section id="ch1">` … `<section id="ch12">`, in order. Renumbering or
inserting one touches six places, and missing any of them leaves the page subtly broken:

1. `<section id="chN">`
2. its `data-screen-label="NN Title"`
3. the `Chapter NN` kicker span
4. the date-span on the right of the kicker rule
5. the nav rail entry (`data-rail-link` + `href`)
6. the overview list entry (`href`)

Every chapter ends with a **sources block** (`<div data-sources="">` holding a two-column `<ul>`),
placed last inside the `<section>`, after the asides. Entries are Harvard style — author (year),
title, venue in italics, then an ADS, DOI or arXiv link — and the prose cites by author–year.
New claims get an author–year in the text and an entry in that chapter's block; keep the
block chronological within its topic groups, not alphabetical. The `data-sources` attribute is
a marker only; nothing in the dc script uses it.

The overview grid is `repeat(auto-fit, minmax(300px, 1fr))`, so a multiple of 12 entries
lands on even rows at both two and three columns. The rail sets `min-width: 940px` sized
for twelve entries; adding more needs that raised.

### Vertical rhythm

Block-level content helpers carry `margin-top: 40px` and rely on **adjacent-sibling margin
collapsing** for correct spacing. A two-column essay block following a figure caption
(`margin-bottom: 0`) gets 40px; following the chapter dek (`margin-bottom: 40px`) it also
gets 40px, not 80px. If you add a new block type, give it a top margin rather than giving
the preceding element a bottom margin, or spacing will double in some places and collapse
to zero in others.

## Design system

The "Classical" system lives in `_ds/classical-*/`; its `readme.md` is the authority. The
rules that actually get violated:

- Take every colour, font, radius and spacing value from tokens — `var(--color-accent-700)`,
  `var(--font-heading)`, `var(--radius-md)`. **There are currently zero hard-coded hex
  colours in `index.html`; keep it that way.**
- Accent is applied as stroke, rule and underline, never as a filled block. Buttons and
  cards are outlined, not filled.
- Paragraph-size accent text uses `--color-accent-700`, not `--color-accent` — the base
  accent only meets 3:1 against the ground, which is enough for chrome and large text but
  not body copy.
- Photographs go through the `.plate` wrapper. Drawn SVG figures do not; they sit in a
  bordered box matching the equation-card chrome.

## Images

Figures are `<image-slot>` custom elements (`image-slot.js`). All fourteen now carry a
`src`: paper figures and the Bullet Cluster images are files in `images/`, the four
photographs are hotlinked from Wikimedia Commons via `Special:FilePath/<name>?width=1600`.
`images/README.md` maps every slot id to its file or URL and source.

**`image-slot` reveals its `<img>` as soon as a `src` attribute is present**, so a `src`
that 404s renders a broken image, not the designed placeholder frame. Paper figures use
`fit="contain"` with the file's exact pixel aspect ratio plus a `max-width` on the figure;
photographs may use `fit="cover"`. Every slot has a `credit`. Chapters 6 and 8 have two
slots (`6a`/`6b`, `8a`/`8b`); chapter 9 has one.

The offline static render (below) shows the local images but not the Commons ones —
those need network, and a broken tile for them in a sandbox is expected.

The element also refuses to render an Unsplash `src` that has no `credit` attribute.

## GitHub Pages

`.nojekyll` at the repo root is **required and easy to delete by accident**. Pages runs
Jekyll by default, and Jekyll silently drops directories whose names start with an
underscore. `_ds/` is the entire design system, so without that file the site deploys
completely unstyled, with no error anywhere.

Keep all paths relative. The site lives at `https://<user>.github.io/<repo>/`, so a
leading-slash `href` or `src` would resolve to the domain root and 404.

## The Claude Design round-trip

`Weak Lensing History Website v2.zip` is a **generated artifact**, not a second source.
It is `index.html` copied in under its original `.dc.html` name alongside the unchanged
support files, because Claude Design imports on that extension. Regenerate it after
changing the page:

```bash
python3 - <<'PY'
import zipfile, shutil, os
os.makedirs('/tmp/dcstage', exist_ok=True)
shutil.copy('index.html', '/tmp/dcstage/Weak Lensing History.dc.html')
for f in ('support.js', 'image-slot.js', '.thumbnail'):
    shutil.copy(f, '/tmp/dcstage/' + f)
shutil.copytree('_ds', '/tmp/dcstage/_ds', dirs_exist_ok=True)
shutil.copytree('images', '/tmp/dcstage/images', dirs_exist_ok=True)
out = 'Weak Lensing History Website v2.zip'
if os.path.exists(out): os.remove(out)
with zipfile.ZipFile(out, 'w', zipfile.ZIP_DEFLATED) as z:
    for root, dirs, files in os.walk('/tmp/dcstage'):
        for f in sorted(files):
            p = os.path.join(root, f)
            z.write(p, os.path.relpath(p, '/tmp/dcstage'))
PY
```

The archive must contain the original's nine entries at the same paths plus the
`images/` files (the page references them relatively); verify with `unzip -l`.

`Weak Lensing History Website.zip` and `HistoryofWeakLensing.rtf` are untouched originals.
Leave them that way.

## Content provenance

All prose derives from `HistoryofWeakLensing.rtf`, a long conversation about the field's
history. It is the factual source; check claims against it before changing them. Several
errors from the original design's placeholder copy were corrected against it and should not
regress:

- The 1990 detection is **Tyson, Valdes & Wenk** (not Tyson, Wenk & Valdes).
- Tyson et al. (1984) found **no signal** and set upper limits; they did not report a
  marginal detection. Kovner & Milgrom (1987) argued those limits were weaker than claimed.
- Randall et al. (2008)'s self-interaction limit of 1.25 cm²/g is **weaker** than the
  earlier ~1 cm²/g, not tighter — more reliable rather than more constraining.
- The Sobral party in 1919 was **Crommelin and Davidson**; Dyson organised from Greenwich
  and did not travel. Michell (1783) argued light feels gravity but did **not** compute the
  deflection; Cavendish (unpublished, c. 1784) and Soldner (written 1801, published 1804) did.
- The 1983 cosmic-shear upper limit is **Valdes, Tyson & Jarvis**, not Valdes, Jarvis & Tyson.
- KiDS-1000 cosmic shear (Asgari et al. 2021) is **S₈ = 0.759 (+0.024/−0.021), ~3σ** from
  Planck. The RTF quotes 0.755 (+0.019/−0.021) and 3.2σ; the published paper is the authority.
- Chapter 12's S₈ values were re-checked against the original abstracts in September 2026 and
  the prose and Fig. 12 carry those numbers, not the RTF's rounded ones: KiDS-450 0.745 ± 0.039;
  DES Y1 shear 0.782 ± 0.027 and 3×2pt 0.773 (+0.026/−0.020); KiDS-1000 3×2pt 0.766
  (+0.020/−0.014); DES Y3 shear 0.759 (+0.025/−0.023) and 3×2pt 0.776 ± 0.017; HSC Y3 0.776
  (+0.032/−0.033, Dalal) and 0.769 (+0.031/−0.034, Li); DES Y3 + KiDS-1000 0.790 (+0.018/−0.014);
  **KiDS-Legacy 0.815 (+0.016/−0.021)** (the RTF says 0.81); DES Y6 shear 0.783 (+0.019/−0.015)
  and 3×2pt 0.789 ± 0.012 (1.8σ from Planck+ACT+SPT in the full space, 2.6σ on S₈ alone);
  Planck 2018 0.832 ± 0.013. Every Fig. 12 row is a filled point with its 68% interval and the
  paper it comes from under the label; do not add a row without both. HSC Y1 (Hamana et al.
  2020, 0.804) is deliberately left out of the figure because an erratum raised it by 2–3%.
  The HSC Y3 + DESI clustering-redshift reanalysis (0.805 ± 0.018) is mentioned in the prose
  without an author because the lead author could not be verified offline — add the citation
  and a sources entry once known.
- Villumsen (1995) is an unpublished preprint; no title or number is given for it because none
  could be verified offline. The same applies to a handful of other entries rendered without a
  title (Kristian 1967, Villumsen 1996, Brainerd & Wright 2000, Kovner & Milgrom 1987,
  Tikhov 1937) — do not invent one.

Chapter 12 carries dated results (DES Y6, KiDS-Legacy, Euclid and Roman milestones) and is
the part most likely to go stale.

## Verifying changes

There are no tests. What has proved worth checking after editing:

- **Structure** — twelve sections in order; every `data-rail-link` and overview `href`
  resolves; `data-screen-label` and `Chapter NN` kickers agree; `<section>`, `<details>`,
  `<figure>`, `<ul>`, `<li>` and `<div>` balanced; exactly twelve `data-sources` blocks; no
  `image-slot` carries a `src`; no absolute paths (the only `http` links are the ADS/DOI/arXiv
  links in the sources blocks, and those have never been resolved from inside a sandbox —
  spot-check them in a browser after editing).
- **Render** — because the dc runtime needs network, layout can be checked offline by
  stripping it: remove the `support.js` tag and the `<script type="text/x-dc">` block,
  drop the `<x-dc>`/`</x-dc>` tags and the `<helmet>` wrapper, and delete
  `ref="{{ rootRef }}"`. The result is plain HTML that renders standalone and is faithful
  for layout and typography. Write it to a scratch file, never over `index.html`. This
  method found two real spacing bugs; it cannot exercise the rail, slider or aside toggles.
- `chromium --headless --no-sandbox --screenshot=out.png --window-size=1280,4200 <url>`
  works for looking at the result. Anchors (`#ch5`) do not scroll in headless capture —
  render a page containing just the chapter of interest instead.
